# Motion Playground Web

Многопользовательское браузерное приложение для демонстрации 2D/3D-анимаций. Исходный код восстановлен из приложения А к отчёту «Motion Playground Web» (разделы А.1–А.11).

## Возможности

- Анимации **Pulse, Rotate, Slide, Fade, Bounce**, регулировка скорости, запуск и остановка, комбинирование вращения и пульсации.
- Переключение 2D/3D и вращение CSS 3D-куба указателем.
- Темы **Dark, Neon, Pastel**.
- Общая сессия: вход по имени, список участников, лента событий, карточки моделей пользователей.
- Независимое состояние каждого участника: настройки одного пользователя не перезаписывают настройки других.
- Обновления сервера через **Server-Sent Events (SSE)** и HTTP API.

## Требования

- **Python 3** (сервер использует только стандартную библиотеку; `pip install` не нужен).
- Современный браузер с поддержкой CSS 3D, Web Animations API, EventSource и JavaScript.
- Для Linux/macOS-скриптов: Bash; для автоматического освобождения порта используется `lsof` (внимание: скрипт может завершить процесс, занимающий порт).

## Быстрый запуск

Из каталога проекта:

```bash
python3 room_server.py
```

Откройте **http://localhost:8080**. Введите имя и нажмите «Войти в сессию». Для проверки совместной работы откройте страницу в другом браузере или на другом устройстве в одной сети по `http://<IP_сервера>:8080`.

На Windows при установленном Python можно использовать:

```powershell
py room_server.py
```

Или запустить `start_server.bat` / `run_local_server.ps1`. На Linux/macOS также доступен `./run_local_server.sh` (при необходимости сначала `chmod +x run_local_server.sh stop-server.sh`). Остановка: `Ctrl+C` в терминале, либо предусмотренные `stop-server.sh` / `stop_server.bat`.

> **Внимание:** `run_local_server.sh` пытается освободить занятые порты 8080–8084, завершая найденные процессы через `kill -9`. Если это нежелательно, запускайте сервер напрямую с собственным портом.

Изменить порт:

```bash
PORT=8090 python3 room_server.py
```

## Как устроено приложение

1. `room_server.py` отдаёт статические файлы и обслуживает API через `ThreadingHTTPServer`.
2. `app.js` управляет локальным объектом и его анимациями.
3. `multiplayer.js` отправляет действия на сервер и подписывается на обновления через `EventSource`.
4. Сервер хранит пользователей и события **в памяти процесса**, рассылает обновления подключённым клиентам. При перезапуске данные сессии теряются.
5. Неактивные участники удаляются по TTL **90 секунд**; лента ограничена **120 событиями**.

### HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/room` | Получить состояние комнаты и список участников |
| `GET` | `/api/events` | SSE-подписка на обновления |
| `POST` | `/api/join` | Присоединиться к сессии |
| `POST` | `/api/ping` | Обновить активность участника |
| `POST` | `/api/action` | Отправить действие/изменение состояния |

Форматы JSON-запросов и событий определены в `room_server.py` и `multiplayer.js`.

## Проверка

Проверка синтаксиса:

```bash
python3 -m py_compile room_server.py
node --check app.js
node --check multiplayer.js
```

Node.js требуется **только для проверки синтаксиса**, не для запуска приложения.

Ручная проверка: запустите сервер, войдите под разными именами в двух вкладках, измените анимацию и режим 2D/3D, проверьте список пользователей и независимость настроек.

## Развёртывание и ограничения

Сервер по умолчанию слушает `0.0.0.0`, поэтому доступен из сети при соответствующих правилах файрвола. Для публикации в интернете используйте HTTPS и обратный прокси (например, Nginx). **В исходном проекте нет полноценной аутентификации, разграничения прав, постоянного хранилища и защиты от злоупотребления API**; не публикуйте его без дополнительной настройки безопасности.
